ระบบในโค้ดปัจจุบันจัดการข้อมูลสิ่งของหรืออุปกรณ์ หมวดหมู่ และประวัติการซ่อม
ยังไม่มีโมดูลข้อมูลลูกค้า และไม่มีระบบบันทึกรายจ่ายประจำวันทั่วไป

[0:00-0:40] เกริ่นนำ

สวัสดีครับ/ค่ะ วันนี้จะนำเสนอระบบ KeepCare เป็นระบบเว็บแอปพลิเคชัน
สำหรับบันทึกและติดตามสิ่งของหรืออุปกรณ์ส่วนตัว เช่น เครื่องใช้ไฟฟ้า
คอมพิวเตอร์ หรืออุปกรณ์ที่มีวันซื้อและวันหมดประกัน

ผู้ใช้สามารถเก็บข้อมูลไว้ในที่เดียว ค้นหารายการได้ และดูประวัติการซ่อม
ช่วยให้ทราบว่าสิ่งของชิ้นนั้นซื้อเมื่อไร ยังอยู่ในประกันหรือไม่
และเคยซ่อมอะไรไปบ้าง

[0:40-1:40] ข้อมูลที่ระบบจัดเก็บ

ข้อมูลสิ่งของประกอบด้วยชื่อ ยี่ห้อ รุ่น หมายเลขประจำเครื่อง
ราคาซื้อ วันที่ซื้อ วันหมดประกัน หมายเหตุ และหมวดหมู่
ระบบยังบันทึกประวัติการซ่อม ซึ่งมีวันที่ รายละเอียด ค่าใช้จ่าย
และหมายเหตุการซ่อม

ผู้ใช้มีบัญชีและบทบาทเป็น USER หรือ ADMIN ส่วนหมวดหมู่สามารถเป็น
หมวดหมู่ส่วนตัวของผู้ใช้ หรือหมวดหมู่ส่วนกลางที่ผู้ดูแลจัดการได้

[2:40-3:50] ระบบทำงานอย่างไร

เริ่มจากผู้ใช้เข้าสู่ระบบด้วย Google ระบบใช้ NextAuth สร้าง session
และระบุรหัสผู้ใช้กับบทบาทไว้ใน session

เมื่อเปิดหน้ารายการ หน้าเว็บจะส่งคำขอไปยัง API เช่น GET /api/items
API ตรวจ session ก่อน จากนั้นใช้ Prisma อ่านข้อมูลจาก PostgreSQL
โดยจำกัดผลลัพธ์ให้เป็นข้อมูลของผู้ใช้ที่เข้าสู่ระบบเท่านั้น
แล้วส่งผลกลับเป็น JSON ให้หน้าเว็บแสดง

เมื่อเพิ่มหรือแก้ไขข้อมูล หน้าเว็บส่งข้อมูล JSON ไปยัง API
API ตรวจสิทธิ์ ตรวจรูปแบบและค่าของข้อมูล แล้วจึงบันทึกลงฐานข้อมูล
หากข้อมูลไม่ถูกต้อง ระบบตอบกลับพร้อมข้อความและรายละเอียดข้อผิดพลาด
ถ้าผู้ใช้ไม่ได้เข้าสู่ระบบ ระบบปฏิเสธคำขอ

[3:50-4:50] CRUD และบริการ API

การทำงาน CRUD มีดังนี้

1. Read หรืออ่านรายการ:
   GET /api/items ใช้แสดงรายการ และ GET /api/items/{id}
   ใช้ดูรายละเอียดสิ่งของหนึ่งรายการ

2. Create หรือสร้างรายการ:
   POST /api/items ใช้เพิ่มสิ่งของ โดยส่งข้อมูลในรูปแบบ JSON

3. Update หรือแก้ไข:
   PUT /api/items/{id} ใช้แก้ไขข้อมูลของสิ่งของตามรหัสรายการ

4. Delete หรือลบ:
   DELETE /api/items/{id} ใช้ลบรายการ โดยตรวจสอบเจ้าของก่อน

เวลาเรียก API ให้เลือก HTTP Method ให้ตรงกับงาน:
GET ใช้อ่านข้อมูล, POST ใช้เพิ่ม, PUT ใช้แก้ไข และ DELETE ใช้ลบ
คำว่า {id} เป็นตัวแทนรหัสจริงของรายการ เช่น /api/items/cma123
ไม่ต้องพิมพ์วงเล็บปีกกา { } ลงใน URL

หมวดหมู่ก็มี API สำหรับอ่าน เพิ่ม แก้ไข และลบ
ส่วนประวัติการซ่อมมี API สำหรับอ่านและเพิ่มรายการซ่อม

[ตัวอย่างกรอกข้อมูลสำหรับเพิ่มสิ่งของ]

ส่งคำขอ POST ไปที่ /api/items
เลือก Body เป็น JSON แล้วใส่ข้อมูลลักษณะนี้:

{
  "name": "Laptop",
  "brand": "Example",
  "model": "Model A",
  "serialNumber": "SN-001",
  "purchasePrice": 25000,
  "purchaseDate": "2026-01-15T00:00:00.000Z",
  "warrantyExpiry": "2027-01-15T00:00:00.000Z",
  "notes": "ใช้สำหรับทำงาน",
  "categoryId": "CATEGORY_ID"
}

คำอธิบายฟิลด์:
- name คือชื่อสิ่งของ เป็นข้อมูลบังคับ ต้องไม่เกิน 100 ตัวอักษร
- brand, model และ serialNumber คือยี่ห้อ รุ่น และหมายเลขเครื่อง
- purchasePrice คือราคาซื้อ ต้องเป็นตัวเลขตั้งแต่ 0 ขึ้นไป
- purchaseDate และ warrantyExpiry คือวันที่ซื้อและวันหมดประกัน
  ใช้รูปแบบวันที่ ISO เช่น 2026-01-15T00:00:00.000Z
- notes คือหมายเหตุ ไม่เกิน 1,000 ตัวอักษร
- categoryId คือรหัสหมวดหมู่ ต้องแทน CATEGORY_ID ด้วยรหัสจริง
  ที่มีอยู่ในระบบ; หากไม่ระบุหมวดหมู่ให้ส่ง null

วันที่ซื้อห้ามเป็นวันในอนาคต และวันหมดประกันต้องไม่ก่อนวันซื้อ
ช่องข้อความที่ไม่จำเป็นสามารถเว้นว่างหรือไม่ส่งมาได้
ตอนแก้ไขด้วย PUT ให้ส่งเฉพาะฟิลด์ที่ต้องการเปลี่ยนได้

[ตัวอย่างค้นหาและกรอง]

เปิด URL:
GET /api/items?search=Laptop&categoryId=CATEGORY_ID

search ใช้ค้นหาจากชื่อ ยี่ห้อ รุ่น หรือหมายเลขเครื่อง
categoryId ต้องแทน CATEGORY_ID ด้วยรหัสจริงของหมวดหมู่
และสามารถใช้ search อย่างเดียวได้

[4:50-5:45] Validation และความปลอดภัย

ระบบใช้ Zod ตรวจสอบข้อมูลก่อนบันทึก ตัวอย่างเช่น ชื่อสิ่งของต้องมีค่า
ข้อความมีความยาวสูงสุด ราคาต้องไม่ติดลบ วันที่ซื้อห้ามเป็นอนาคต
และวันหมดประกันต้องไม่อยู่ก่อนวันที่ซื้อ

การตรวจสอบทำทั้งใน schema และใน API อีกชั้นหนึ่ง
กรณีส่ง JSON ผิดรูปแบบหรือข้อมูลไม่ผ่าน validation จะตอบสถานะผิดพลาด
โดยไม่บันทึกข้อมูล

ด้านสิทธิ์ ทุกคำขอที่จัดการข้อมูลต้องผ่านการตรวจ session
และการอ่าน แก้ไข หรือลบสิ่งของจะผูกกับ userId ของผู้ใช้
จึงไม่สามารถเข้าถึงรายการของผู้ใช้อื่นได้เพียงแค่ทราบรหัสรายการ

[5:45-6:25] Search และ Filter

หน้าแสดงรายการค้นหาได้จากชื่อ ยี่ห้อ รุ่น หรือหมายเลขประจำเครื่อง
และกรองตามหมวดหมู่ได้

ตัวอย่างเช่น GET /api/items?search=laptop&categoryId=รหัสหมวดหมู่
API จะประกอบเงื่อนไขค้นหาและหมวดหมู่ แล้วคืนเฉพาะรายการที่ตรงกัน
โดยยังจำกัดผลลัพธ์ไว้กับผู้ใช้ปัจจุบัน

[6:25-7:10] ขอบเขตและแนวทางต่อยอด

ข้อสำคัญคือ KeepCare เวอร์ชันปัจจุบันเน้นข้อมูลสิ่งของและการซ่อม
ยังไม่มีข้อมูลลูกค้า และค่าใช้จ่ายการซ่อมไม่ใช่ระบบบัญชีรายจ่ายประจำวัน

หากต้องการให้ตรงกับระบบร้านค้าหรือระบบบริหารทั่วไป สามารถต่อยอดโดยเพิ่ม
โมดูลลูกค้า และโมดูลรายจ่ายประจำวัน พร้อมตารางฐานข้อมูล API validation
และหน้าจอ CRUD ของแต่ละโมดูล โดยใช้แนวทางยืนยันตัวตนและจำกัดสิทธิ์
แบบเดียวกับที่มีอยู่

[7:10-7:30] สรุป

สรุปแล้ว KeepCare มีการจัดการข้อมูลสิ่งของแบบ CRUD
มีการตรวจสอบข้อมูล มีการยืนยันตัวตนและกำหนดสิทธิ์

จุดเด่นคือข้อมูลสิ่งของกับประวัติการซ่อมถูกรวมอยู่ในระบบเดียว
